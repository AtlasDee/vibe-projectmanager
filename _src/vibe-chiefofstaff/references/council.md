# 决策参谋：参谋会

一个要拿主意的问题，从背景门槛走到用户拍板。铁律见 SKILL.md 第 4 节，这里写每一步怎么做。

```
背景门槛 → 打分路由 → 议程确认 → 各角色独立发言一轮 → 唱反调 → 汇总 → ⏸ 你拍板 → 存档两层
```

单角色咨询（打分 1～2）只走背景门槛、路由、该角色发言、⏸ 拍板（有要定的事时）四步，不开唱反调，汇总就是该角色的发言。

## 0 开会前先读

1. `幕僚/背景档案.md`：没有的，按第 1 节「零背景」处理，不另做完整建档；超过 90 天的，问用户是先花几分钟更新还是照旧用，照旧用的在汇总里标 `背景已过期（更新于 <日期>）`。
2. `幕僚/决策/决策索引.md` 和相关的决策文件（只读第二层，SKILL.md 第 4 节第 6 条）：
   - 有同主题的生效决定：告诉用户「<日期>定过 <DEC-xxx>：<决定>」，问这次是复核它还是另议；
   - 要讨论的方案正是标了 `不再提起` 的提议：停下，告诉用户当时否决的理由，用户说重开或给出新信息才继续。
3. 跑一次 `scripts/decision_scan.py`，复核日已到的决定和逾期的跟进，顺带在开场一句话提一下，不展开。`幕僚/决策/` 还不存在时脚本报目录不存在（退出码 2），这是正常的：跳过，开场说一句「还没有决策日志」即可。

## 1 背景门槛

参谋会产出空泛建议，几乎都是因为背景不够。开会前逐项判定：

| 项 | 够用的样子 | 不够的样子 |
|---|---|---|
| 目标 | 可量化、有期限：「明年 Q2 前月活到 50 万」 | 「做大」「提升体验」 |
| 关键数字 | 与这个问题直接相关的几个数：预算或现金余量、人数、收入或成本、转化、周期 | 一个数都没有，或只有和问题无关的数 |
| 硬约束 | 碰不得的线：截止日、预算上限、法规、不能动的人或系统 | 没说，且问题明显受约束（如裁员、合规、跨境、签长约、数据出境） |
| 可选方案 | 桌上已有的两三个选项；「要不要做 X」算两个选项（做 / 不做）；或明确说「还没有方案」 | 只有一句「怎么办」 |
| 拍板人 | 谁最后定；用户自己定就是用户 | 不清楚，且决定明显超出用户权限 |

**数字要自洽**：五项都在，还要用几道简单的算术把关键数字互相核一遍——转化率乘基数和客户总数对不对得上、收入除以客户数和价目对不对得上、余量按毛支出还是净烧。对不上的，这一项按不够算，开会前先问用户哪个数对、口径是什么；用户也说不清的，照开，在汇总里列为假设冲突（第 6 节），行动项第一条是核口径。

判定结果三档：

- **够**：五项都够、数字自洽，直接开。
- **缺一部分**：目标、关键数字都够，其余有缺。照开，缺的项写在汇总的背景门槛一行。
- **缺关键**：目标或关键数字不够（含数字对不上）。先问，再开。用户答不上或说直接开的，照开，但：
  - 每个角色的置信度最高为低；
  - 汇总的背景门槛一行写 `缺关键（缺 <项>）——以下是方向性的，不是可执行的结论`；
  - 行动项第一条是把缺的数补上，负责人和期限由用户给。

**怎么问**：

- 先按第 2 节打分、选出上场角色，再从这些角色的「开口前要的数」（`references/roles.md` 第 2 节）里挑问题；排序按「这一个答案最能改变结论」。
- 最多 3 个问题。一次只问一个、每一轮只问一个，不预告后面的问题；一个问题里可以合并两个紧密相关的小问（如「做什么、12 个月想达到什么」）。
- 用户只答了一部分的，同一个问题不追问第二次，没答的部分记 `未采集`，接着问下一个或开会。
- 问的同时告诉用户：可以说直接开，以及直接开的后果（上面三条）；上场角色可以一句话预告，正式的议程确认（第 3 节）放在问答结束之后。
- 用户的回答里出现新数字，按 `references/background.md` 第 3 节记成待补。

**零背景**（没有背景档案）：不先做完整建档。门槛的 3 个问题就是全部要问的：第一问固定为「做什么、卖给谁、12 个月想达到什么」，后两问按上面的排序从角色要的数里挑。建档的其余必填项（阶段、人数、管理者类型、第一难题）不另问，记 `未采集`。会后问用户要不要把问到的写成第一份背景档案（`references/background.md` 第 2 节「最少几项」）。

## 2 打分与路由

**复杂度打分**：基础分 1，下面每满足一条加 1，封顶 5。

| 加分项 | 例子 |
|---|---|
| 影响两个以上部门 | 涨价同时影响销售、产品、客服 |
| 难以撤回 | 裁员、签长约、换核心架构、融资条款 |
| 预计角色之间会有分歧 | 财务要省、营收要投；技术要还债、产品要上新 |
| 直接影响团队里的人 | 编制、调岗、考核 |
| 有合规或法律层面 | 数据出境、合同责任、监管问询 |

| 分数 | 做法 |
|---|---|
| 1～2 | 单角色咨询：路由到一个主角色 |
| 3 | 两个角色：主角色 + 一个辅角色，汇总 |
| 4～5 | 参谋会：3～5 个角色 + 唱反调 |

**直接升为参谋会**（不看分数）：难以撤回且动到两个以上团队的预算、编制或优先级；用户说「大家怎么看」「我要多几个角度」「帮我从几个角度想想」之类；话题正落在用户自认的盲区（背景档案里的「自认短板」）。

**不要多叫角色**：答案明显属于一个角色的纯专业问题；用户只要一个框架、不是要做决定；再加角色只添噪声。

**路由**：单角色和两个角色的咨询，按 `references/roles.md` 第 3 节的话题表选主角色和辅角色；参谋会按该文件第 4 节的议题组合选，再按这次问题删到最多 5 个，并确认第 3 节的主角色在场。路由不清时，问用户一个澄清问题再路由。

## 3 议程确认（参谋会才有）

开会前给用户看一眼，等确认：

```
参谋会：<议题>
要定的事：<一句话>
议程：<2～3 个具体问题>
上场角色：<角色及选它的理由，各一行>
背景门槛：<够 / 缺一部分 / 缺关键>；缺：<项>
```

用户可以加减角色、改议程。单角色和两个角色的咨询不需要确认，直接做。

## 4 各角色独立发言一轮

**独立性做法**（SKILL.md 第 4 节第 2 条）：

- **能起子代理时**：每个角色一个子代理，并行跑。给它的只有：背景档案中与议题相关的部分、用户在这次对话里给的相关事实（如刚贴来的消息、刚发生的投诉）、议程、该角色在 `references/roles.md` 第 2 节的那一行、下面的发言格式。不给其他角色的发言，不给幕僚长的倾向。
- **不能起子代理时**：在同一会话里按角色顺序写；写每个角色前重读议程和背景，不引用、不回应前面角色说过的话。汇总里写 `独立性：同一会话内顺序生成，偏弱`。

**发言格式**（每个角色都用，最多 5 条要点）：

```
## <角色> · <日期>

要点（最多 5 条）：
- <发现> （已核实 / 假设）【依据：背景档案的哪个数或约束，或用户哪句话】
- ...

主张：<一句话的明确立场>
置信度：高 / 中 / 低
最可能让我改主意的情况：<具体条件，例如 获客成本超过 X>
出了自己的领域：<有就写，没有写 无>
```

每个角色的自检：每条要点都标了已核实或假设；已核实的写了依据；没有越界替别的角色下结论；置信度和背景门槛一致（缺关键时最高为低）。

## 5 唱反调（参谋会才有）

高管教练（`references/roles.md` 第 2 节）拿到所有角色的发言后，只挑毛病，不汇总、不给自己的方案：

- 哪里大家同意得太容易？（几个角色不约而同给了同一个结论，又都没写依据，是危险信号）
- 哪些假设是大家共有、却没人验证的？
- 谁不在场？（一线、客户、法务、执行这件事的团队）
- 哪个风险没人提？
- 哪个角色出了自己的领域？
- 哪条建议把公司名换掉也成立？（SKILL.md 第 6 节「建议落在背景上」）

唱反调的输出不超过 5 条，每条指向具体角色的具体要点。

## 6 汇总

汇总不是把每个角色的话依次复述一遍，是取舍：

1. **读全**：读完所有发言和唱反调，找三种信号：共识（两个以上角色独立得出同一结论）、冲突（一方说 X 另一方说非 X，或对同一数据读法不同、抢同一份资源、看的时间跨度不同）、空白（关键的一面没人谈、关键的风险没人提、写进去的假设没人质疑）。
2. **提共识**：最多 3 条，每条写是哪几个角色得出的。超过 3 条说明是在罗列，不是在汇总。
3. **摆分歧**：每个冲突写清四件事：谁和谁、各自的立场和理由、分歧的类型、分歧的实质（如「这不是技术问题，是能承受多大风险的问题」）。

   | 类型 | 样子 |
   |---|---|
   | 资源 | 两个角色要同一份预算、编制或时间 |
   | 优先级 | 对眼下最要紧的是什么意见不同 |
   | 时间跨度 | 一方看本季度，一方看一年半 |
   | 假设 | 两方的模型建立在互不相容的假设上（如增速 15% 对 8%）；这类要指出该用哪一方的数重算，由用户定 |

4. **出行动项**：从共识和没有冲突的部分推出，最多 5 条，每条具体（「梳理质检流程找出瓶颈」而不是「优化流程」）、有负责人、有期限、写清不做的后果。负责人和期限用户没给的写 `待定`，不编。多的列为待议。
5. **压成一个拍板问题**：通常是那个只能靠价值取舍解决的冲突。写成一个问题、两三个选项、各自的代价和各自背后站着哪几个角色。确实是两件不相干的事，拆成两份汇总。

**汇总格式**：

```
# <议题> · 参谋会汇总 · <日期>

背景门槛：<够 / 缺一部分（缺 <项>）/ 缺关键（缺 <项>）——以下是方向性的，不是可执行的结论>
独立性：<子代理并行 / 同一会话内顺序生成，偏弱>
上场：<角色列表>

## 结论先行
<一两句：大家在哪些事上已经一致，剩下哪一件要你定>

## 共识
- <共识> （<角色>、<角色>）

## 分歧
<冲突名>：<角色 A> 主张 <X>，因为 <理由>；<角色 B> 主张 <Y>，因为 <理由>。
类型：<资源 / 优先级 / 时间跨度 / 假设>。实质：<真正在争什么>

## 唱反调
- <问题> （指向 <角色> 的第 <n> 条）

## 建议的行动
1. <行动> · 负责人 <待定或姓名> · 期限 <待定或日期> · 不做会怎样 <后果>

## 待你拍板
<一个问题>
- 选项 A：<做法>。代价：<代价>。（<支持的角色>）
- 选项 B：<做法>。代价：<代价>。（<支持的角色>）

## 附：各角色发言
<全文，或指向讨论记录>
```

**汇总自检**：

- 压缩：三分钟能读完、读完知道要做什么吗？不能就删。
- 诚实：分歧是照实摆出来了，还是被抹平了？抹平的分歧之后会变成意外。
- 具体：行动项能直接动手，还是只是目标？
- 一个问题：拍板问题是不是只有一个？
- 背景：换一家公司这份汇总还成立吗？成立就是没落在背景上。

**僵局**：每条共识都有反面、每个行动都带冲突、拍板问题其实是三个时，照实写 `各角色在这件事上确实分裂`，摆出两条路及后果；能做小范围、限期的试验的，写成选项（「先按 X 跑 30 天，以 <指标> 判断，再定」）；需要外部信息（市场数据、外部顾问）的，写成行动项。假的共识比僵局更糟。

## 7 ⏸ 你拍板

汇总后停下：

```
⏸ 待你拍板：<拍板问题>
可以：批准某个选项 / 改了再定 / 否决 / 追问某个角色
```

- **批准**：按选项写决策文件。
- **修改**：用户的改法直接覆盖角色的意见，不反驳、不再搬出「某角色说过」；改了什么写进决策文件的「用户改动」。
- **否决**：否决的提议写进决策文件的否决清单并标 `不再提起`；整件事不定的，只写讨论记录，第二层不写。
- **追问**：只让被追问的角色补一轮，补的内容进讨论记录；其他角色不跟着再说。
- **没有回应**：本次汇总记为 `待拍板`，只写讨论记录；下次简报列进「待你定」。

## 8 存档两层

拍板后按 `references/decision-log.md` 第 2～4 节写：

1. 第一层：讨论记录全文（议程、各角色发言、唱反调、汇总、用户的回应）写进 `幕僚/决策/讨论记录/<YYYY-MM-DD>-<简称>.md`。没拍板的也写。
2. 写第二层前做冲突检查（`references/decision-log.md` 第 5 节），有冲突先给用户处理。
3. 第二层：决策文件 + 索引一行。
4. 告诉用户：记了几个决定、几条跟进、几个否决的提议，存在哪。

## 9 常见失败与对策

| 失败 | 对策 |
|---|---|
| 所有角色都同意 | 检查是不是没有独立：重跑发言，让每个角色先写「反对这个方向最有力的理由」 |
| 漂亮但空泛 | 回到背景门槛，缺的数问出来；删掉换了公司名仍成立的条目 |
| 讨论发散 | 每个角色限 5 条；跑题的事记成待议，回到议程 |
| 角色越界（财务替产品下结论） | 唱反调点出来，汇总不采用越界的那条 |
| 把旧讨论当共识 | 开会只读第二层；讨论记录要用户点名才读 |
| 角色太多 | 删到 5 个以内，留与分歧最相关的 |
| 替用户做了决定 | 汇总只摆选项和代价；推荐只在用户要时给，且单列 |
