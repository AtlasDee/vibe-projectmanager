# 决策日志

两条路线共用一个日志：参谋会拍板的结论、日常一句「我们定了 X」，都记在这里。

## 1 两层

| 层 | 放什么 | 位置 | 谁来读 |
|---|---|---|---|
| 第一层：讨论记录 | 参谋会全文：议程、各角色发言、唱反调、汇总、用户的回应；被否决的论点也在 | `幕僚/决策/讨论记录/<YYYY-MM-DD>-<简称>.md` | **不自动读**。只在用户点名要看时读 |
| 第二层：决策结论 | 只放用户拍板过的决定、跟进事项、用户改动、否决的提议 | `幕僚/决策/DEC-<编号>-<简称>.md` + `幕僚/决策/决策索引.md` | 每次开参谋会、做简报和周报时读 |

为什么分开：讨论记录里有大量没被采纳的说法，下次开会如果读到它们，模型很容易把「当时有人这么说」当成「当时定了」。第二层只有拍板过的东西，读它不会混淆。

- 第二层只追加：决定不删，只会被新决定取代（第 4 节）。
- 讨论记录超过 90 天的，可按年移进 `讨论记录/归档/<YYYY>/`；移之前问用户。
- 不是参谋会来的决定（第 3 节直接记录）没有第一层，决策文件的「讨论记录」写 `无（直接记录）`。

## 2 决策文件

一份决定一个文件，文件名 `DEC-<三位编号>-<简称>.md`。`scripts/decision_scan.py` 按下面的表格读，表头和字段名不要改。

```markdown
# DEC-<编号> <决定的标题>

| 字段 | 内容 |
|---|---|
| 日期 | <YYYY-MM-DD> |
| 状态 | <生效 / 已被取代 / 作废> |
| 决定 | <一句话说清定了什么> |
| 拍板人 | <姓名或岗位> |
| 负责人 | <一个人> |
| 截止日 | <YYYY-MM-DD 或 待定> |
| 复核日 | <YYYY-MM-DD 或 待定> |
| 理由 | <为什么选这个而不是别的，一两句> |
| 用户改动 | <用户改了角色的建议时，改了什么、为什么；没有写 无> |
| 来源 | <参谋会 / 单角色咨询 / 直接记录 / 会议：<会议名>> |
| 讨论记录 | <讨论记录/<YYYY-MM-DD>-<简称>.md 或 无（直接记录）> |
| 取代 | <DEC-xxx 或 无> |
| 被取代于 | <DEC-xxx 或 无> |
| 项目指针 | <该决定在某项目 pm 目录下另有 ADR 时写 <项目>/ADR-xxx；没有写 无> |

## 否决的提议

| 提议 | 理由 | 标记 |
|---|---|---|
| <被否决的提议> | <为什么否决> | 不再提起 |

## 跟进事项

| 编号 | 事项 | 负责人 | 截止 | 状态 | 完成日 | 结果 |
|---|---|---|---|---|---|---|
| F-1 | <具体动作> | <一个人> | <YYYY-MM-DD 或 待定> | 未完成 | | |
```

**字段规则**：

| 字段 | 规则 |
|---|---|
| 决定 | 一句话。要两句才说得清，拆成两个决定 |
| 拍板人 | 谁最后定的；用户自己定就写用户的岗位 |
| 负责人 | 一个人或一个岗位。写两个的，第一个负责 |
| 截止日、复核日 | 用户给才写；不给的写 `待定`，下次简报列进「待你定」。不自动填 14 天这类默认值。复核日一般在截止日之后两到四周，由用户定 |
| 理由 | 必填。「因为定了」不算理由 |
| 用户改动 | 照实写，不弱化、不省略 |
| 否决的提议 | 讨论中明确否决的都列上，每条都标 `不再提起` |
| 跟进状态 | `未完成` / `进行中` / `已完成` / `取消`；已完成写完成日和一句结果，取消写理由（写进结果列）。在别处跟踪的写成指针行：事项写 `见 <文件> <编号>`，其余各列留空，`scripts/decision_scan.py` 不计入统计 |

## 3 直接记录

用户说「我们定了 X」「记个决策」时：

1. 问清（一次一个，已经说了的不再问）：定了什么、谁拍的板、谁负责、什么时候到期、有没有跟进事项。给不了的写 `待定`。
2. 用户贴来会议纪要或群聊的，从中摘出决定和跟进事项，给用户核对后再记；纪要里没写明的负责人和日期，不从上下文猜。纪要来自 vibe-assistant（`助理/纪要/`）的，行动项已在助理的行动项台账里跟：跟进事项只写一行指针 `见 助理/行动项.md <编号>`，状态以台账为准，这里不另记负责人和截止。
3. 判断记在哪（第 7 节）。
4. 做冲突检查（第 5 节）。
5. 写决策文件、在索引追加一行，告诉用户编号和文件位置。
6. 设定里「决策记在哪」不是本地的（云文档、群聊、表格），另外按那个格式生成一段可粘贴的文字；**写到外部要用户在当前这条消息里明确同意**（SKILL.md 第 6 节「外部写操作要授权」），默认只给文字由用户自己贴。本地文件照样写，作为唯一真源。

## 4 索引与取代

`幕僚/决策/决策索引.md` 每个决定一行，只追加；状态变了改这一行的状态列，不删行。

```markdown
# 决策索引

| 编号 | 日期 | 决定 | 负责人 | 复核日 | 状态 | 文件 |
|---|---|---|---|---|---|---|
| DEC-001 | <YYYY-MM-DD> | <一句话> | <负责人> | <复核日> | 生效 | DEC-001-<简称>.md |
```

**取代**：新决定推翻或修改旧决定时，新文件的「取代」写旧编号；旧文件的状态改为 `已被取代`、「被取代于」写新编号；索引里两行都更新。旧文件的其余内容不动。

## 5 写入前的冲突检查

写第二层之前，对照索引和生效的决定查三类：

1. **不再提起**：新决定正是某份决定里标了 `不再提起` 的提议。
2. **同主题矛盾**：已有一个生效的决定管着同一件事，结论不同。
3. **负责人冲突**：同一件事在两个生效的决定里分给了不同的人。

`scripts/decision_scan.py` 会列出所有标了不再提起的提议和所有生效决定，供比对；是不是同一件事，由你读了判断，拿不准的当冲突问用户。

有冲突时停下：

```
⚠ 决策冲突
新的：<内容>
冲突的：<DEC-xxx>（<日期>）<内容>
可以：用新的取代旧的 / 两条合并成一条 / 先放着，由你定
```

撞上不再提起的：

```
⛔ 这个提议在 <日期> 的 <DEC-xxx> 里被否决过，理由：<理由>
要重开，请明确说要重开 <主题>，或告诉我有什么新信息
```

用户重开的，新决定的理由里写明重开的依据。

## 6 查询、逾期与复核

先跑脚本拿到准确的清单，再读需要的文件：

```bash
python scripts/decision_scan.py <幕僚目录下的 决策 目录> [--as-of YYYY-MM-DD] [--soon 7]
```

输出：概况（生效、已被取代、作废的决定数；跟进事项按状态的数）、逾期的跟进（逾期天数）、`--soon` 天内到期的跟进、复核日已到的生效决定、`待定` 的截止日与复核日、标了不再提起的提议、索引与文件对不上的地方、读不准的文件。只汇总，不判断。

- 用户问「之前定过什么」：按主题在索引里找，再读对应的决策文件；默认只列最近 10 条，要全部的再给。
- **复核日已到**：在简报或对话开头提一句「<日期>定过 <DEC-xxx>：<决定>，复核日到了，要过一下吗？」只提，不自行复核。
- **完成跟进**：把那一行的状态改为 `已完成`，写完成日和一句结果。不删已完成的行，历史就是记录。

## 7 与项目决策日志的分工

装了 vibe-projectmanager、且这个决定属于某个项目时：

| 决定的性质 | 记在哪 |
|---|---|
| 某个项目内的取舍（技术选型、范围、方案） | 那个项目 `pm/决策日志/ADR-xxx`（按 vibe-projectmanager 的写法）；这里的决策文件「项目指针」写 `<项目>/ADR-xxx`，决定一栏写一句摘要 |
| 动到已放行的 PRD、里程碑、范围或预算 | 先走那个项目的变更请求；批准后这里只记管理层的决定和指针 |
| 跨项目、或不属于任何项目（人事、预算分配、对外合作） | 只记在这里 |

同一个决定不在两处各写一份完整内容：一处写全，另一处只写指针。
