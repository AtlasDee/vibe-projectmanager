# 角色：登记、话题路由、议题组合

角色是模拟的视角，不代表真实的人（SKILL.md 第 4 节第 8 条）。每个角色的价值在于它**看问题的方法**和**开口前要的数**：要的数拿不到，这个角色只能给方向。

## 1 自定义角色

团队不是创业公司、或有些视角这里没有（风控、客服、渠道、法规事务、某个业务线负责人），在 `幕僚/幕僚设定.md` 的「自定义角色」里登记，格式与第 2 节一行相同：代号、管什么、看问题的方法、开口前要的数。自定义角色和下面的角色一样参与路由；同一议题里与内置角色重叠的，用自定义的。

团队里没有的岗位（如没有法务），照样可以叫这个角色，但汇总里写 `该视角团队内无人承担，落地需外部支持`。

## 2 角色登记

| 代号 | 角色 | 管什么 | 看问题的方法 | 开口前要的数 |
|---|---|---|---|---|
| CEO | 首席执行官 | 方向、全局取舍、对外关系 | 推演三种未来（顺利 / 一般 / 糟糕），看哪个选择在三种里都站得住 | 12 个月目标、现金或预算余量、最大的威胁 |
| CFO | 财务 | 现金、预算、单位经济、融资 | 把算式写出来，每个结论都能复算 | 预算或现金余量、月支出、收入与成本结构、回本周期 |
| COO | 运营 | 流程、目标管理、执行节奏、规模化 | 画出流程，找排队最长的那一步 | 现有流程的步骤与周期、人手、瓶颈处的积压量 |
| CTO | 技术 | 架构、技术债、技术选型、扩容 | 先查证、再分析、再给动作 | 系统规模与流量、故障率、团队技能、技术债清单 |
| CPO | 产品 | 路线图、优先级、做不做、产品与市场匹配 | 从用户要完成的事出发，不从现有功能出发 | 目标指标、关键功能的使用率、用户反馈、需求池 |
| CRO | 营收 | 销售、上市策略、定价、客户画像 | 算漏斗：每一级的量和转化 | 漏斗各级转化、客单价、销售周期、在途商机 |
| CMO | 市场 | 定位、渠道、品牌、内容 | 先起草、再自我批判、再改 | 各渠道成本与转化、目标人群、竞品定位 |
| CHRO | 人力 | 招聘、组织、绩效、薪酬、文化 | 数据加共情：既看流失率，也看人为什么走 | 编制与空缺、流失率、关键岗位风险、薪酬带宽 |
| CISO | 安全合规 | 安全、合规审计、风险 | 概率 × 影响 | 资产与数据类别、适用法规、过往事件 |
| GC | 法务 | 合同、条款、知识产权、法律暴露 | 逐条看暴露面：最坏情况赔多少、谁担 | 合同原文、管辖地、金额与责任上限 |
| CDO | 数据 | 数据战略、数据权属、数据资产 | 这份数据驱动哪个决定，没有决定就不值得建 | 数据来源与授权范围、用途、存储位置 |
| CAIO | AI | AI 战略、模型选型、评测、AI 风险与成本 | 没有评测就不上线 | 用例、准确率要求、调用量与单价、出错的代价 |
| CCO | 客户成功 | 留存、流失、客户分层、续约 | 先看毛留存，再看净留存 | 留存与流失率、客户分层、流失原因 |
| VPE | 研发交付 | 交付节奏、研发效能、研发招聘、团队结构 | 先算吞吐和周期时间 | 周期时间、部署频率、在制量、人数 |
| 高管教练 | 唱反调 | 不发言，只评审所有角色的发言 | 找太容易的共识、没验证的共同假设、缺席的人、没人提的风险、越界 | 所有角色的发言 |

角色的主张要带「最可能让我改主意的情况」；开口前要的数缺了的，在要点里写 `缺 <数>，以下为假设`。

## 3 话题路由

先按话题找主角色，再看辅角色要不要上（按 `references/council.md` 第 2 节打分，3 分及以上才上辅角色）。表里的分数是典型情况，以 `references/council.md` 第 2 节实际打分为准。

| 话题 | 主 | 辅 | 典型分 |
|---|---|---|---|
| 预算、现金、财务模型、融资时机 | CFO | CEO、COO | 2～3 |
| 过桥融资还是削减成本 | CFO | CEO、COO | 5 |
| 定价模式 | CFO | CRO、CPO | 4 |
| 先招人还是保余量 | CFO | CHRO、COO | 4 |
| 招聘、辞退、文化、绩效 | CHRO | COO | 2～3 |
| 合伙人或核心管理者冲突 | CHRO | CEO | 4 |
| 下一步做什么、砍不砍某个功能 | CPO | CTO、CRO | 2～3 |
| 自研还是采购 | CPO | CTO、CFO | 4 |
| 技术债和新功能怎么分 | CTO | CPO | 3 |
| 架构、扩容、要不要拆服务 | CTO | COO、CFO | 1～4 |
| 研发越来越慢、交付周期、团队怎么分 | VPE | CTO、CHRO | 2～3 |
| 成交难、销售流程、客户画像 | CRO | CPO、CMO | 2～3 |
| 走大客户还是中小客户、进新市场 | CRO | CPO、CFO、CMO | 4～5 |
| 流程、目标管理、反复出的瓶颈 | COO | CTO | 1～2 |
| 定位、渠道投入、品牌 | CMO | CRO、CFO | 2～3 |
| 安全事件、数据泄露 | CISO | CTO、CEO、COO | 5 |
| 合规审计、隐私法规、监管问询 | CISO | GC、CTO | 2～4 |
| 合同能不能签、条款、知识产权归属 | GC | CFO、CTO | 2～3 |
| 能不能用客户数据训练、数据能不能变现 | CDO | GC、CAIO | 3 |
| 用接口、微调还是自建模型，AI 成本失控 | CAIO | CTO、CFO | 2～3 |
| 留存下滑、该不该放掉某类客户 | CCO | CRO、CPO | 2～3 |
| 要不要转型、要不要接受收购、三年战略 | CEO | 参谋会 | 5 |

跨领域的问题（如「涨价会不会伤留存」）取影响最大的一方为主，另一方为辅；分不清的问用户这件事最怕的后果是什么，那个后果归谁管谁就是主。

## 4 参谋会的议题组合

参谋会按议题从这里起步，再按这次的问题删到最多 5 个；唱反调的高管教练每次都在，不占名额。议题带合规或法律面（跨境、数据、长约、监管）而组合里没有 GC 或 CISO 的，把与这次问题最不相关的一个换成 GC 或 CISO，并在议程确认里写明换了谁。

| 议题 | 上场角色 |
|---|---|
| 进新市场、扩张 | CEO、CMO、CFO、CRO、COO |
| 产品方向 | CEO、CPO、CTO、CMO |
| 招聘与组织 | CEO、CHRO、CFO、COO（研发招聘加 VPE） |
| 定价 | CMO、CFO、CRO、CPO |
| 技术方向 | CTO、CPO、CFO、CISO |
| 合同、法律暴露 | GC、CEO、CFO |
| 数据战略、训练数据权属 | CDO、CAIO、GC、CISO |
| AI 战略、模型选型、AI 风险 | CAIO、CTO、CDO、CFO |
| 留存与客户成功 | CCO、CRO、CPO |
| 研发交付与团队结构 | VPE、CTO、CHRO、CFO |

发言顺序（顺序生成时用）：先要数的、后定方向的——CFO、CRO、CMO、CPO、CTO、VPE、COO、CHRO、CISO、GC、CDO、CAIO、CCO、CEO。并行跑子代理时顺序无关。
